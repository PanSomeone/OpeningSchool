## 1. 工程结构

单仓库、多 Gradle 模块，依赖方向永远指向 `core`：

```
app/                     宿主壳：导航、路由、AppGraph 装配
core/model/              纯 Kotlin 数据模型（课表、时间、周次）
core/data/               数据与运行时：存储、插件运行时、原生加载器、市场下载
core/ui/                 通用 Compose 组件、插件视图渲染器、AndroidView 嵌入
core/plugin-api/         对外插件协议（适配器 + 声明式视图 PluginView）
core/plugin-sdk/         原生插件 SDK（HostPlugin / PluginHost / NativeScreen）
feature/home/            主页组件画布
feature/timetable/       课表、导入、设置
feature/plugins/         插件页与插件市场
feature/settings/        设置、公告、更新
adapter/zhengfang/       内置教务适配器
adapter/*-external/      外部适配器示例（独立 APK 协议）
plugin/hotwater/         内置插件：热水
plugin/scores/           内置插件：成绩
plugin/sample-native/    示例：APK 形态原生插件（已上架源码）
plugin/calendar/         示例：dex 形态原生插件（已上架，华农校历）
```

| 关注点 | 文件 |
| --- | --- |
| 宿主接线 / 路由 | `app/src/main/java/com/openschedule/app/AppShell.kt`、`OpenScheduleApp.kt` |
| JS 插件运行时 / 沙箱 / 依赖树 | `core/data/.../PluginRuntime.kt`、`RhinoSandbox.kt`、`PluginDependencyGraph.kt` |
| 原生插件发现 / 加载 / 生命周期 | `core/data/.../NativePluginCatalog.kt`、`NativePluginLoader.kt`、`NativePluginRuntime.kt` |
| 模块安装 / 清单校验 | `core/data/.../PluginModuleStore.kt`、`ModuleManifestValidator.kt` |
| 存储 / 视图白名单校验 | `core/data/.../PluginDataStore.kt`、`PluginViewValidator.kt` |
| 渲染与嵌入 | `core/ui/.../PluginViewRenderer.kt`、`NativePluginView.kt` |
| 插件页 UI | `feature/plugins/.../PluginsScreen.kt` |

## 2. 构建与运行

环境：**JDK 17+**、Android SDK（compileSdk 37）、minSdk 26。

```bash
./gradlew test                  # 单元测试（88+ 项）
./gradlew assembleDebug         # 调试包
./gradlew assembleRelease       # 签名正式包 → app/build/outputs/apk/release/
```

- 签名读取仓库根目录 `keystore.properties`；**密钥不入库、不回显**。
- 正式包开启 R8。`app/proguard-rules.pro` 必须保留 `kotlin.**`，否则插件 dex 调用 Kotlin 标准库会 `NoClassDefFoundError`。
- 每次出包**递增 versionCode**，否则新旧包无法区分。

## 3. 三种插件形态

| 形态 | `apiVersion` | `type` | 入口 | 运行方式 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 网页导入模块 | `1` | `web-importer` | `main.js` | Rhino 沙箱执行 `parse()`，返回 JSON 课表 | 教务网页解析 |
| 应用模块 | `2` | `app` | `main.js` | Rhino 常驻 `apply(ctx)` / `dispose()` | 带页面、组件、存储的 JS 插件 |
| 原生插件 | `2` | `native` | `classes.dex` 或 APK | `InMemoryDexClassLoader` / `DexClassLoader` 加载 `HostPlugin` | 需要真正的原生 View / 性能敏感 |

要点：

- 模块装在 `filesDir/modules/<id>/`，**不安装 APK**，无桌面图标、不进系统应用列表。
- APK 形态靠 `<queries>` 里的 `com.openschedule.plugin.NATIVE` 标记 action 发现，不申请 `QUERY_ALL_PACKAGES`。
- 原生插件是**同进程同 UID 的可信代码，没有沙箱**；上架前必须人工审核。
- 已停用 / 加载失败的插件仍显示在列表中，可点开看状态卡并重试。

## 4. 插件清单 plugin.json

```json
{
  "id": "hzau.calendar",
  "name": "校历（华农 2026—2027-1）",
  "description": "一句话说明",
  "version": "1.0.0",
  "apiVersion": 2,
  "type": "native",
  "entry": "classes.dex",
  "entryClass": "com.openschedule.plugin.hzau.calendar.CalendarPlugin",
  "iconKey": "date",
  "author": "OpeningSchool"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 全局唯一，`^[a-z0-9][a-z0-9._-]{1,63}$` |
| `name` | 是 | 列表显示名 |
| `version` | 否 | 语义化版本，升级时变化会触发热重载 |
| `apiVersion` | 是 | `1`（web-importer）或 `2`（app / native） |
| `type` | 是 | `web-importer` / `app` / `native` |
| `entry` | 否 | 入口文件，默认 `main.js`；原生必须指向 `.dex` |
| `entryClass` | native 必填 | 实现 `HostPlugin` 的全限定类名 |
| `startUrl` | web-importer 必填 | http(s) 教务入口 |
| `requires` | 否 | 依赖的其他模块 id，按拓扑序加载；缺失则阻塞下游 |

校验在安装与加载两处都会执行：`ModuleManifestValidator`（纯 Kotlin，可直接单测）。

## 5. JS 插件 API（apiVersion 2）

```js
function apply(ctx) {
  ctx.storage.set("count", "0");
  ctx.events.on("timetable.updated", function (payload) { /* ... */ });
  ctx.ui.homeWidget({
    id: "counter",
    title: "计数",
    iconKey: "star",
    columns: 1, rows: 1,
    view: { type: "text", text: "0" }
  });
  ctx.ui.screen({
    id: "main", title: "计数页", iconKey: "star",
    render: function () { return { type: "column", children: [
      { type: "text", text: "你好" },
      { type: "button", text: "加一", action: "inc" }
    ]}; }
  });
}
function dispose() { /* 释放 */ }
```

- `ctx` 能力：`storage`（命名空间 KV）、`events`（异步总线 + `action:<name>`）、`ui.homeWidget`、`ui.screen`、`services`（跨插件调用）。
- 视图是**声明式白名单**：`column / row / card / text / icon / button / spacer / divider`；不合法节点由 `PluginViewValidator` 降级，不会崩溃。
- 沙箱限时 6 秒；模块之间靠 `requires` 组成插件树。

## 6. 原生插件 SDK

依赖：`:core/plugin-sdk`（`compileOnly`，运行时由宿主提供）。

```kotlin
class DemoPlugin : HostPlugin {
    private lateinit var host: PluginHost

    override fun onCreate(host: PluginHost) {
        this.host = host
        host.onEvent("timetable.updated") { payload -> host.log(payload) }
    }
    override fun onDestroy() {}
    override fun screens(): List<NativeScreen> =
        listOf(NativeScreen("main", "原生页面", "science") { ctx -> MyView(ctx) })
    override fun widgets(): List<NativeWidget> =
        listOf(NativeWidget("counter", "原生计数", "science", 1, 1) { ctx -> MyView(ctx) })
}
```

`PluginHost` 提供 `pluginId / hostVersion / dataDir() / log() / getString / putString / remove / onEvent / emit`。

硬性约束：

- **不要**把 Kotlin / AndroidX / 宿主类打进插件包；只依赖 Android 框架与 `core/plugin-sdk`。
- 宿主 `NativePluginApi.VERSION = 2`，清单 `apiVersion` 必须 ≤ 2，否则显示「需要插件 API ≤ 2」且不加载。
- 同一 `id` 的模块升级（version / entry / 路径变化）会自动卸载旧实例再加载。
- 页面 View 每次进入重建；状态请落到 `host.putString`。

## 7. 打包 .osplugin

`.osplugin` 就是一个 zip，根目录放 `plugin.json` + 入口文件：

```bash
# 原生 dex 模块（以校历为例）
./gradlew :plugin:calendar:assembleDebug
cp plugin/calendar/build/intermediates/dex/debug/mergeProjectDexDebug/*/classes.dex market/samples/hzau-calendar/
cd market/samples/hzau-calendar
zip -r ../../../dist/hzau.calendar-1.0.0.osplugin plugin.json classes.dex
sha256sum ../../../dist/hzau.calendar-1.0.0.osplugin   # 写入目录 catalog.json
```

- 取 `mergeProjectDexDebug/<n>/classes.dex` 比 `classes.jar` 可靠。
- `d8` 对 Kotlin 2.4 产物会警告 `malformed kotlin.Metadata`，产物仍有效。
- 限制：解压后 ≤ 8 MB、文件 ≤ 200、`plugin.json` ≤ 64 KB。

## 8. 插件市场协议

`market/catalog.json`（同时内置一份 `feature/plugins/src/main/assets/market_catalog.json` 作离线兜底）：

```json
{
  "version": 2,
  "plugins": [{
    "id": "hzau.calendar",
    "name": "校历（华农 2026—2027-1）",
    "description": "…",
    "category": "校园信息",
    "version": "1.0.0",
    "url": "https://gitee.com/PanSomeone/OpeningSchool/raw/main/plugins/hzau.calendar-1.0.0.osplugin",
    "sha256": "760a8302…",
    "sizeBytes": 11055,
    "iconKey": "date",
    "type": "module"
  }]
}
```

- 目录优先级：Gitee 远端 → GitHub 远端 → 本地缓存 → 内置 assets。
- `url` 支持 `asset://<文件名>`，从 APK 内置 assets 读取，用于离线示例。
- 下载后必须校验 `sha256`；并行下载上限 3。

## 9. 发布流程

1. 递增 `app/build.gradle.kts` 的 `versionCode` / `versionName`。
2. `./gradlew test assembleRelease`，记录 `sha256sum` 与文件大小。
3. 更新根目录 `update.json`（version / title / notes / pageUrl / apkUrl / fallbackApkUrl / sha256 / sizeBytes）。
4. 在 `announcements.json` 追加一条公告。
5. 提交、打 tag（`v1.1.4`）、推送**源码仓库 GitHub**。
6. 发布 Release：GitHub 上传 APK；Gitee 同步作为默认更新源。
7. **Gitee 只存分发文件**（README、`update.json`、`announcements.json`、`plugins/`、`market/catalog.json`、发行版附件），**不推源码**。
8. 发布后验证：`update.json` 可访问、APK 可下载、SHA-256 与清单一致。

版本历史与回滚记录见 [BACKUP.md](BACKUP.md)；不要移动已发布的 tag。

## 10. 排错手册

```bash
adb logcat | grep -iE "NativePlugin|\[Market\]|\[Plugin\]"
```

| 现象 | 先查什么 |
| --- | --- |
| 插件行点进去只有状态卡 | 卡片红字即真实原因：`Didn't find class`（dex/类名错）、`NoClassDefFoundError`（少了 `kotlin.**` keep）、`需要插件 API ≤ N`（清单 apiVersion 过高） |
| 插件的 classes.dex 被当脚本解析 | 旧版宿主的 `PluginRuntime` 未过滤 `type=native`，升级宿主即可；日志特征 `illegal character: … (classes.dex#2)` |
| 市场看不到某个插件 | 远端目录优先于内置 assets，检查 Gitee 上的 `market/catalog.json` 是否已更新 |
| 下载后「未校验」/校验失败 | `sha256` 与文件不一致，重新打包并更新目录 |
| 原生插件装好却不出现 | 点「重新扫描已安装插件」；APK 形态还需确认 `<queries>` 标记 action |

调试技巧：正式包不能 `run-as`，可用 debug 包覆写 `files/modules/<id>/classes.dex` 制造加载失败，验证状态卡与「重试加载」。
